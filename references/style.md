# 视觉系统与版式

本规范总结课程讲义式表达，不宣称与任何官方模板逐页一致。参考 `assets/demo.pptx` 的全新匿名样例；用户提供新基线时，当前基线优先。不要读取或要求任何作者本机的私人模板。

## 视觉词汇

- 16:9；示例尺寸1280×720 CSS px，即12192000×6858000 EMU。
- 纯白背景；正文 `#222222`，红色强调 `#C00000`，辅助灰 `#606060`。
- 中文微软雅黑或可用的协调无衬线字体；数学用Cambria Math或原生数学字体。不附带或假设安装专有字体。
- 标题通常30–32pt，正文20–22pt，解释至少尽量18pt。图注可12–14pt；不能把主讲内容塞成小字。
- CSS px与pt不同，1pt=4/3px。API若使用CSS px，32pt应按约42.67px处理。
- 标准版心左x64–80、右至x1200，上方标题，正文一般从y145开始。页底留来源与实际页码空间。
- 内容带是标题以下、页底来源与页码以上的区域。16:9 且高 720 的页上约为 y145–y612，中线约 y378：上半部约 y145–y378，下半部约 y378–y612。流程图、表格或证据图若在上半部结束，下半部不得整段留空。
- 标题层级和红色用法整稿统一；红色用于问题、关键词和重要结论，不把所有正文染红。

## 版式原型

### 封面

纯白、居中、充分留白。自上而下在版心内留出四段，论文信息不要缩进页脚：

- 上方一行简短汇报类型。
- 中部红色主标题。论文讲解（单篇／精读）时，主标题就是论文题目，通常 30–32pt。
- 题目下方单独两行：作者，以及会议或期刊与年份。这两行至少 18pt，必须出现在第 1 页版心内，不能只写在页脚或 ≤15pt 来源行。
- 再下方是本次署名与日期。

不是论文讲解时，封面仍用主标题加署名／日期，不必填写作者和会议。新任务不得默认继承 demo 的文字。封面可参考 `assets/demo.pptx` 的留白；demo 有的页超过每页 40 词上限，不作为字数样本。

### 层次讲义

左上主标题，2–4个纵向小节。红色短关键词紧接一至两行黑色解释，用缩进和间距而不是厚框组织。实际阅读日期与概念讲述顺序分开。

### 公式与解释

左侧公式约宽630，右侧变量及含义约宽460。先说公式回答的问题，再解释关键项、单位和适用条件。公式优先原生或可编辑数学文本；帽符号、上下限、分式线都需渲染核对。

### 证据图与读图

左图宽约760–780，右侧说明宽约330。图的外框要进入内容带下半部；原图本身只占上半部时，在下半部放一行结论或一句读图说明，不把说明写成新的正文段落。保留坐标、图例、色条和条件；解释符号含义、局部观察及有条件的结论。密集原图按论点选择子图，不能直接缩整页截图。

结果页没有可嵌入的原图时，放原生示意图块（流程、结构或对照），或单独做一页并在版心写明「缺图」、缺的是哪一张、为什么暂缺。不能只用文字条代替这张图。禁止为填满下半部而把正文字号降到 18pt 以下，或把备注里的解释搬回屏幕。

### 表格

用原生表格，表头和单元格都可选中修改。表格落在内容带上半部或中部时，下半部接一行结论或一句读表说明。不要把行高拉空来假装填满，也不要把字号缩小后多塞正文。单元格不是结果图的替代品：没有原图的结果页仍按上一节，使用原生示意图或「缺图」页。

### 论文工作／个人收获双栏

左右约各546宽。左栏2–3点论文工作，右栏2–3点本次笔记中的理解。个人想法标明，不能写成论文已证明；底部可有一句受条件约束的红色结论。

### 逻辑图

只有依赖、更新或顺序确实需要解释时才用反馈环、四步流程或对应时间轴。图和文字可编辑，箭头表达真实逻辑。每栏一幅简单解释图和两条短说明；汇报归纳框架须标为示意，不冒充原文固定算法。

四格流程图（或同样停在内容带上半部的中等高度示意图）排完后，下半部必须再有一块，三选一：一行结论、一句读图说明，或第二行更小的原生示意图。写在上半部格子旁边的短说明，不算下半部已填。禁止靠缩小字号，或再加正文要点来填这半区。

### 总结

2–4个短标签加解释，呈现已经理解或完成的事项。用户只要总结时，不额外添加未来计划或致谢页。

## 避免

不要用超大标题、全稿重复卡片、密集小字、渐变、阴影、无关照片或大色带代替清晰表达。正文先精简，再调整布局。四格流程、表格或证据图不要停在内容带上半部而让下半部整段留白；没有原图时不要只用文字条充作结果图。可选蓝色图解仅在明确要求或当前基线需要时使用，不能随机与黑红页拼接。

统一页码依照最终实际顺序，不依赖PPTX中slideN的文件名。风格匹配不代表继承源模板的科学结论或历史排版错误。
