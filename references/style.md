# 视觉系统与版式

本规范总结课程讲义式表达，不宣称与任何官方模板逐页一致。参考 `assets/demo.pptx` 的全新匿名样例；用户提供新基线时，当前基线优先。不要读取或要求任何作者本机的私人模板。

## 适用范围

本页是新稿的默认视觉系统。当前用户参考文件优先；纯风格迁移只改约定的视觉属性，不能执行精简正文、补下半部内容、拆页或重排页码。局部公式/动画素材保持用户给定布局、比例和颜色，不强加封面、来源条或黑红配色。留白由实际内容决定，不为填空增加观点。

## 视觉词汇

- 16:9；示例尺寸1280×720 CSS px，即12192000×6858000 EMU。
- 纯白背景；正文 `#222222`，红色强调 `#C00000`，辅助灰 `#606060`。
- 中文微软雅黑或可用的协调无衬线字体；数学用Cambria Math或原生数学字体。不附带或假设安装专有字体。
- 字阶见下一节。不能把主讲内容塞成小字。
- 标准版心左x64–80、右至x1200，上方标题，正文一般从y145开始。页底留来源与实际页码空间。
- 内容带是标题以下、页底来源与页码以上的区域。16:9 且高 720 的页上约为 y145–y612，中线约 y378：上半部约 y145–y378，下半部约 y378–y612。流程图、表格或证据图若在上半部结束，下半部不得整段留空。
- 标题层级和红色用法整稿统一；红色用于问题、关键词和重要结论，不把所有正文染红。

## 字阶

新稿按这一档。当前用户参考文件的字号优先于默认值。CSS px 与 pt 不同，1pt = 4/3 px。API 若使用 CSS px，32pt 按约 42.67px，18pt 按约 24px。

| 角色 | 字号 |
| --- | --- |
| 封面主标题、内容页标题 | 32pt |
| 正文（含解释） | ≥20pt，硬底 18pt |
| 图注、图表标签 | ≥16pt |
| 来源 | 13pt，放在页底来源带 |

结果页标题写成这一页的主张（claim-title），例如「选择性复制接近满分」，不用「实验结果」或只写图号、章节名。整篇怎么排，见 [文章梳理](narrative.md)。标题仍是 32pt。

结构审计对页脚／来源带以外、显式字号小于 18pt 的可见正文记 `font_below_min`。来源带里的页码、以及带来源标记且 ≤15pt 的来源行，不按这条正文硬底计。相对白底对比度低于 4.5:1 的文字色，以及用作文字的 `#BFBFBF`，记 `low_contrast_text`。两条都只警告，不改变退出码。16pt 图注低于正文硬底，也可能被记上，需要时把图注提到 18pt。

## 版式原型

### 封面

纯白、居中、充分留白。自上而下在版心内留出四段，论文信息不要缩进页脚：

- 上方一行简短汇报类型。
- 中部红色主标题。论文讲解（单篇／精读）时，主标题就是论文题目，32pt。
- 题目下方单独两行：作者，以及会议或期刊与年份。这两行至少 18pt，必须出现在第 1 页版心内，不能只写在页脚或 ≤15pt 来源行。
- 再下方是本次署名与日期。

不是论文讲解时，封面仍用主标题加署名／日期，不必填写作者和会议。新任务不得默认继承 demo 的文字。封面可参考 `assets/demo.pptx` 的留白。demo 只参考版式。屏幕上放多少由这一页的主题决定，见 [屏幕密度](density.md)。可编辑封面用 `scripts/layout_helpers.py` 的 `add_cover`，作者和会议写在版心。见 [版式构件](layouts.md)。

### 层次讲义

左上主标题，2–4个纵向小节。红色短关键词紧接一至两行黑色解释，用缩进和间距而不是厚框组织。这一页只讲一个主题；20pt 放不下就拆页，不缩字。实际阅读日期与概念讲述顺序分开。

### 公式与解释

左侧公式约宽630，右侧变量及含义约宽460。先说公式回答的问题，再解释关键项、单位和适用条件。公式优先原生或可编辑数学文本；帽符号、上下限、分式线都需渲染核对。

### 证据图与读图

左图宽约760–780，右侧说明宽约330。图旁写这一页主题需要的关键数字、对照和各 panel 的读解，都留在屏幕上。图的外框要进入内容带下半部；原图本身只占上半部时，在下半部放一行结论或读图说明，不把讲解写成段落。保留坐标、图例、色条和条件。密集原图按论点选择子图，不能直接缩整页截图。读解在 20pt 下装不下或挡住图时，拆成两页。

结果页没有可嵌入的原图时，放原生示意图块（流程、结构或对照），或单独做一页并在版心写明「缺图」、缺的是哪一张、为什么暂缺。不能只用文字条代替这张图。禁止为填满下半部而把正文字号降到 18pt 以下，或把备注里的讲解段落搬回屏幕。数字和对照本来就在屏幕上。

### 表格

用原生表格，表头和单元格都可选中修改。表格落在内容带上半部或中部时，下半部接一行结论或一句读表说明。不要把行高拉空来假装填满，也不要把字号缩小后多塞正文。单元格不是结果图的替代品：没有原图的结果页仍按上一节，使用原生示意图或「缺图」页。实现用 `add_table`：20pt、固定行高、上半部的表必须带下半部那一句。不要用文本框拼表。见 [版式构件](layouts.md)。

### 论文工作／个人收获双栏

左右约各546宽。左栏2–3点论文工作，右栏2–3点本次笔记中的理解。个人想法标明，不能写成论文已证明；底部有一句受条件约束的红色结论。文字双栏用 `add_two_column`。架构双栏仍用 `diagram_helpers.py` 的节点，不要混用。见 [版式构件](layouts.md)。

### 逻辑图

算法、架构和多步流程必须用图，决策表见 [示意图](diagrams.md)。依赖、更新或顺序需要解释时用反馈环、四步流程、判断菱形或对应时间轴。图和文字可编辑，箭头表达真实逻辑。每栏一幅简单解释图和两条短说明；汇报归纳框架须标为「汇报归纳」或「示意」，不冒充原文固定算法。

16:9 页上的常用尺寸：

- 四步流程：节点高约 0.9 英寸、宽约 2.4–2.8 英寸，箭头间隙约 0.36 英寸。整行放在内容带上半部（约 y145–y378）。
- 判断：菱形约 1.6 英寸见方，分支写在箭头旁。
- 双栏架构：左右两栏各约 5 英寸，中间留缝，栏内模块纵向堆叠。一页节点大约 8 个，最多 12 个。
- 描边和箭头用 `#222222`，需要强调的节点描边用 `#C00000`，填充保持白。不要套用主题蓝。

四格流程图（或同样停在内容带上半部的中等高度示意图）排完后，下半部必须再有一块，三选一：一行结论、一句读图说明，或第二行更小的原生示意图。写在上半部格子旁边的短说明，不算下半部已填。禁止靠缩小字号，或把讲解段落贴进这半区。

### 图优先版式

按内容换一种，避免连续三页同一版式：

- 全页示意图：标题下整块是流程或架构，下半部只留一行结论。
- 左文右图：左边一条结论和不超过三条短句，右边是原生示意图。
- 左图右文：证据图或公式图在左，右边是读图或符号说明。宽图（宽高比大于约 1.6）改为全宽，说明放到图下。

这三种都要守住内容带下半部。没有原图的结果页仍然用原生示意图或「缺图」页，不能退化成纯文字条。

### 总结

2–4个短标签加解释，呈现已经理解或完成的事项。用户只要总结时，不额外添加未来计划或致谢页。

## 避免

不要用超大标题、全稿重复卡片、密集小字、渐变、阴影、无关照片或大色带代替清晰表达。正文先精简，再调整布局。四格流程、表格或证据图不要停在内容带上半部而让下半部整段留白；没有原图时不要只用文字条充作结果图。可选蓝色图解仅在明确要求或当前基线需要时使用，不能随机与黑红页拼接。

统一页码依照最终实际顺序，不依赖PPTX中slideN的文件名。风格匹配不代表继承源模板的科学结论或历史排版错误。

页脚来源和数字页码用 `add_footer`。图加可编辑图注用 `add_picture_caption`。定义用白底细红框 `add_callout`，不要阴影和渐变。节分隔只用一行标题 `add_section_divider`，不做议程列表。这些都在 [版式构件](layouts.md)。
