# 示意图：图优先

组会讲论文时，算法、架构和多步流程要让人在十秒内靠图看懂。这一页写何时必须画图、用什么画、什么时候才能生图。配色仍是本 skill 的白底、`#222222`、`#C00000`、`#606060`，不换主题。

与 [风格与版式](style.md) 的下半部填充、[内容与证据](content.md) 的原图保真、[公式](formulas.md) 的公式页一起用。结构检查见 [验收](qa.md) 和 `scripts/audit_pptx.py`。

用户只要求修改已有图中的符号或添加动画时，保持图的分块、关系和颜色，不按本页的新稿默认样式重画。点击进入动画见 [局部编辑与动画](scoped-edits.md#点击进入动画)。

## 优先级

同一页按这个顺序选，靠前的做得到就不要退到后面：

1. 可编辑的原生形状（矩形、圆角矩形、菱形、箭头）。
2. 论文里的原图（结果和证据页）。
3. 手绘矢量或 python-pptx 形状，并标明「汇报归纳」或「示意」。
4. 用户**明确**要求时的 AI 概念草稿。草稿不是证据。
5. 版心写明「缺图」的缺口页。

`editable` 做失败就停在这一页并说明缺什么。不要静默改成整页图片，还说成品可编辑。

## 何时必须用示意图

| 页面意图 | 判定信号 | 强制动作 |
| --- | --- | --- |
| 算法 / 伪代码流程 | 算法、步骤、训练流程、推理 | 原生流程图（方框加箭头）。伪代码不超过约 10 行，并且旁边有流程图。禁止只有项目符号的算法页 |
| 解题 / 问题分解 | 多步推导、分支决策 | 原生流程；判断用菱形。关键式子另起一页，按公式版式 |
| 架构 / 模型结构 | Transformer、Mamba、encoder–decoder、系统模块 | 原生框图（矩形加连接线）。只借用结构怎么分块，匿名重画，不抄别人的私图 |
| 方法对比 / pipeline | A→B→C、多组件依赖 | 分层结构图，或把 Mermaid 节点表落成原生形状 |

大纲里这一页的 `visual_plan.kind` 写 `native_diagram`，`must_diagram` 为 true。材料里没有可画的结构时，`kind` 写 `gap`，版心写清缺的是哪一张、为什么暂缺。两种都算合规。只有文字、没有形状、没有连接线、没有原图、也没有「缺图」，不合规。

结构审计只看这一页的标题，不扫正文。标题里要有概念词（方法、算法、架构、框架、流程，或 method、algorithm、architecture、pipeline、framework）才会记 `algorithm_page_missing_diagram`。Mamba、Transformer 这类模型名本身不触发。第 1 页封面，以及已经有表格、图表、图片、带图片回退的公式或原生示意图的页，不警告。所以封面标题里出现模型名、结果表里出现 Transformer++、小结正文里提到 Transformer，标题是「方法」但页上已有合格 OMML，都不应为了消警告而改词。

`text_ok` 只给封面、过渡和纯讨论收获。方法段和结果段不要标 `text_ok`。整稿没有视觉的页，目标不超过 30%；论文精读的方法段和结果段几乎每页都要有图、表、公式或原生示意图。

## 何时嵌入论文原图

| 条件 | 动作 |
| --- | --- |
| 结果或证据页，材料里有 Fig.N | 用 `pdftoppm` 或 PyMuPDF 裁出。保留坐标轴、单位、图例、色条、panel 字母。图注写 `Source: Author et al., Year, Fig.x` |
| 用户给了复现图 | 原样嵌入，旁边写读图说明。hash 记入 `run_state` 的 `source_assets` |
| 宽高比大于约 1.6 | 全宽。否则图左文右，版心仍按 [风格与版式](style.md) |
| 表是证据 | 重建原生表格，不截一张表的图 |

没有原图时，不要让生图模型画一条「看起来像实验结果」的曲线。用原生示意，或做「缺图」页。

## 何时可以生图

只有用户明确说要生图、AI 示意图、graphical abstract 或机制概念图时才可以。

| 可以 | 不可以 |
| --- | --- |
| 用户点名要求概念图 | 没授权就调用生图 API |
| 图上或备注标明「概念示意 / 草稿」，不当定量证据 | 用生成图仿造实验曲线、热图、显微图或数值 |
| 生成图上的关键标签，改用 PPT 里的原生文字重写（生成图容易写错字） | 把生成图写成论文 Figure |
| 架构和流程能用形状表达时，仍然先用形状 | 用整页生成图代替可编辑的算法流程框 |

不发明数值，不画机构标志。本 skill 不绑定 OpenRouter 或其他付费接口；没有这些接口不得当成制作失败。

## 引擎（Linux，无 PowerPoint）

按这个顺序，做得到就停：

1. **主路径：`python-pptx` 形状。** `scripts/diagram_helpers.py` 把节点和边写成圆角矩形、矩形、菱形和箭头。只依赖 Python 标准库和 `python-pptx`。这是组会默认路径。
2. **可选：Mermaid 落到原生形状。** 节点表与本脚本的 JSON 相同。环境里如果有 `mmdc` 或 mermaid2pptx，可以拿来做布局参考或转换；没有就用手摆的形状。不得因此改成整页 PNG，也不把 officecli、Go 二进制写成硬门槛。
3. **节点很多、需要自动分层时才用 Graphviz DOT。** 输出仍尽量转成形状。只能嵌高 DPI PNG 时，备注写「非原生可编辑」。
4. **论文原图**按上一节提取。
5. **生图**只走上一节，而且排在形状和原图之后。

结构图、依赖图、架构图优先想成分层的方框和连线。时序和状态可以写成 Mermaid 再落成形状。需要忠实复现数学几何时才考虑 TikZ；组会默认不装整套 TikZ。

## 版式尺寸

幻灯片 12192000×6858000 EMU（16:9）。内容带约 y145–y612，中线约 y378。图若停在上半部，下半部仍要有一行结论、一句读图说明，或第二行更小的示意图。不要为了填空缩小字号。

- 一行流程：节点高约 0.9 英寸，宽约 2.4–2.8 英寸，箭头间隙约 0.36 英寸，整行放在内容带上半部。
- 判断：菱形约 1.6 英寸见方，标签保持一行。放不下时缩小字号或把菱形略加宽，不要把「完成？」折成两行。分支文字写在箭头旁。
- 双栏架构：左右两栏各约 5 英寸，中间留缝，栏内模块纵向堆叠。栏内竖向箭头要留出能看清的间距，不要只剩一个箭头尖。
- 一页节点大约 8 个，最多 12 个。再多就拆页。`diagram_helpers.py` 超过 12 个会拒绝写入。
- 不是论文原图的流程，图下或节点旁写「汇报归纳」或「示意」。

避免连续三页用同一种图版式。三种版式见 [风格与版式](style.md) 的「图优先版式」。

## 脚本

一页的规格是 JSON：

```json
{
  "title": "训练流程：四步示意",
  "layout": "row",
  "nodes": [
    {"id": "read", "label": "读入", "shape": "round", "accent": true},
    {"id": "encode", "label": "编码", "shape": "round"},
    {"id": "update", "label": "更新", "shape": "round"},
    {"id": "score", "label": "评价", "shape": "round"}
  ],
  "edges": [
    {"src": "read", "dst": "encode"},
    {"src": "encode", "dst": "update"},
    {"src": "update", "dst": "score"}
  ],
  "conclusion": "顺序是汇报归纳，不是原文算法。",
  "source": "来源：匿名示意，不是论文实验。",
  "page": "2"
}
```

`shape` 取 `round`、`rect`、`diamond`、`ellipse`。双栏时把 `layout` 设为 `columns`，并给节点 `"column": 0` 或 `1`。

```text
python scripts/diagram_helpers.py --spec flow.json --output out.pptx
python scripts/diagram_helpers.py --samples assets/diagram-samples/figure-first.pptx
```

`--samples` 会写出三页匿名样张：四步流程、双栏架构、公式加符号说明。样张只示范版式，数字和步骤都不是论文结果。`assets/demo.pptx` 可以另有一页图优先示例，不替换前面各页的内容。

颜色锁死：填充白，普通描边和箭头 `#222222`，强调节点描边 `#C00000`，正文 `#222222`，标题 `#C00000`。去掉主题样式，避免被主题蓝盖掉。用 matplotlib 画数据图时，可以套 `assets/presentation.mplstyle`：色序 `#222222`、`#C00000`、`#606060`、`#BFBFBF`，并去掉上边框和右边框。

论文里已经给出的柱状对比，用 `add_bar_chart`（`scripts/chart_helpers.py`，`diagram_helpers.add_bar_chart` 转过去）。它写原生 `c:chart`：没有图例和图表标题，数据标签打开，数值轴从 0 起并且隐藏。要强调的那一根是 `#C00000`，其余是 `#BFBFBF`。python-pptx 有时写出负数 `c:axId`，函数会改成正数，否则 Office 架构校验失败。柱上的数由调用方传入，并且应当是论文里的数。示意流程仍用形状。

短折线和散点也在同一个文件：`add_line_chart`、`add_scatter_chart`。仍是可编辑图表，没有图例和标题，数由调用方传入。做法和限制见 [版式构件](layouts.md)。不要把流程页改成折线。

## 运动讲解

用户明确要求推导动画、几何运动或三维直觉时，才使用 [运动讲解](motion.md)。ManimGX 渲染 MP4，再由 `scripts/embed_motion.py` 嵌进 PPTX。这一页不代替上面的原生形状，也不代替公式页的 OMML。本机没有 ManimGX（Python 3.13 或 3.14）时，算法页仍用本节的形状，并在备注说明没有渲染动画。

## 硬禁止

- 禁止纯文字的算法页、架构页、多步流程页。
- 禁止用生成图冒充论文原图或实验结果。
- 禁止为了填满下半部而缩小字号，或把备注搬回屏幕。
- 禁止把 Unicode 堆成假公式，或在屏幕留下 LaTeX 源码。公式另见 [公式](formulas.md)。
- 禁止用 ManimGX 的影片代替原生流程图、架构图或可编辑公式。影片只在用户明确要求运动讲解时追加。
